# /issue-map

> [!NOTE]
> **Editing this skill?** Keep everything here **general**: no project, person, company or stack names. It works with GitHub Issues only, like `dev-next`, and reads the same `### Blocked by` body section and labels that `dev-next`'s `references/new-issue.md` defines. The generator is `scripts/issue_map.py`; a change to what the map shows is a pull request on that file.

The map is **a transient snapshot**: `docs/issue_map/issue_map.html` is never committed, built on the machine that
looks at it, and carries a banner saying who built it and when. The source of truth stays the GitHub issues
(`BASE_CLAUDE.md`, *Work tracking*). This skill only ever rebuilds that local file.

## What the map shows

- **Nodes**: every issue, open and closed, whatever its label. Epics (label `epic`) sit in their own far-left column,
  joined to their stories by dashed purple lines (GitHub's native sub-issue link). Epics and closed issues start hidden.
  Each box shows its number and progress icon, its epic, its title, its assignees and up to three label chips.
- **Links**: the union of GitHub's native blocked-by relation and the `### Blocked by` body section. Nothing else.
  A link to an epic, to an issue that does not exist, or that closes a cycle is dropped. Those links, and every open
  issue whose body section and native relation disagree, are data problems: the side pane lists each in plain words
  (what was found, what it changes on the map, how to fix it on GitHub), and the footer sentence, also printed by the
  generator, says whether the two sources agree on every open issue and names every dropped link.
- **Levels** (the columns): 0 when nothing blocks an issue, else one more than the highest level among its blockers.
- **Background colour** = who takes it: `agent-ready` green, `needs-human` red, `outside-change` blue, no readiness
  label yellow, epic purple. **Icon** = progress: blocked 🔒 (an open blocker, even when assigned), in progress 🔨
  (assigned), ready 🟢, closed = red cross.
- Click a box to light up its whole chain (upstream and downstream) with a card (labels, description, blockers,
  what waits on it, an "Open on GitHub" button) that can be dragged by its title; double-click opens it on GitHub;
  Esc closes a menu, then the card. Four filter menus (who takes it, progress, assignee, labels, each option with
  shown/total and "only") hide issues; hidden issues leave the map and the rest close up. Dark theme, light when the
  system asks for it.

## Steps

1. Run the generator — from any checkout of the project, main or worktree; it always writes into the **main
   checkout**, so every terminal rebuilds the same file:

   ```
   python .claude/skills/issue-map/scripts/issue_map.py            # --silent mode: rebuild only
   python .claude/skills/issue-map/scripts/issue_map.py --open     # user asked to see it: rebuild, then open in the browser
   ```

   Use `python3` where `python` is not on the path. It needs `gh` signed in and Python 3.9 or newer, no packages.
   One run is one issue list plus one GraphQL call per 25 issues (for the native links), so even a large tracker
   takes seconds, not minutes. It prints two lines: the path with the counts and the "generated by … on …" stamp,
   then the footer sentence about the links.
2. **User asked to see it** ("show me the issue map", `/issue-map` with no argument): use `--open`, then reply with
   one line: the path, how many issues it holds, and the "generated by … on …" stamp the script prints.
3. **Called with `--silent`** (by `/dev-next`, or any other skill): run without `--open`, print nothing to the user,
   and carry on. A failure here (no `gh`, network down) is logged in one line and never stops the calling skill.

## Rules

- Never commit `issue_map.html`, never open a pull request for it, never copy it into `docs/` elsewhere. If it is
  shared, the banner says it is stale by construction. The generator adds the file to the clone's local
  `.git/info/exclude` when the project's `.gitignore` does not already ignore it, so it never shows up as a change;
  a project may add `docs/issue_map/issue_map.html` to `.gitignore` too, but does not have to.
- A skill that calls this one runs it **in the background, as its own command, never chained** with another: on a
  large tracker the API calls run past a shell timeout and would push the chained command into the background too.
- Never change the generator in a project: it carries the `.orion-managed` marker and `orion update` overwrites it.
  A change to what the map shows is a change to orion itself (the generator), not to the project.
